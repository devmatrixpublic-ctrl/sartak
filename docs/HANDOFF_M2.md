## Run everything (from the repo root)

```bash
(cd server && pip install -e ".[dev]" && pytest -q)                       # backend, 182 tests
RUN_SLOW=1 RUN_E2E=1 pytest ops -q                                        # ops, held-out scoring, 57-check end-to-end run, smoke-test proof
pytest -q detector/tools                                                  # schema, UPI mapping, watch-list, freeze pre-flight
(cd detector && gradle --max-workers=1 test)                              # Kotlin detector: 36 vectors, parity, fuzz (22 tests)
python ops/e2e/run_e2e.py                                                 # real Kotlin decisions driving the real server
python detector/tools/freeze_preflight.py --skip-gradle                   # is the detector ready to freeze? (today: no)
```
The Android app needs the Android SDK and JDK 21 (CI builds it). Step-by-step run instructions, including the physical-phone route and what is untested, are in `docs/RUN_THE_APP.md`.

## Numbers, and how far to trust them

All detection results are on **simulated** data (SatarkSim). On the validation split: recall 93.1% (95% CI 90.7-95.0), false alarms 0.071%
(CI 0.028-0.146), calibration alpha' = 0.0008. **Cross-validation puts recall nearer 91.8%**, so the 93% target is borderline, not secured.
At a realistic fraud rate (about 1 in 1.47 lakh) precision would be under 1%, roughly one true alert per 113. The family-emergency scam is the weak
playbook (56.6% recall). A brand-new install detects as well as a mature personal history on this data, so **per-user adaptive baselines are
untested, not proven**; do not present them as a measured result.

## Traps already hit

* **Maven Central rate-limits (HTTP 429).** Retry `gradle --max-workers=1 ...`; Gradle keeps what it downloaded.
* **`gradlew` must be committed executable (mode 100755).** `git update-index --chmod=+x` is silently undone by a later `git add -A` if the file on disk is not
  executable; `chmod +x` first. `ops/ci/test_workflows.py` now pins it.
* **The CI job named "Android build (skipped until app/ exists)" really builds the app now**; only its name is stale.
* **GitHub Actions raw logs may not be downloadable** from restricted environments; the Android job prints its Gradle log tail as an annotation on failure.
* **Production boot needs `server/certs/google_attestation_roots.pem`**, so the Render deploy waits on M4's roots decision.
* **The stub rule has an allowlist** (`ops/ci/planned_stubs.txt`) for exactly the plan's own dev-token markers; the release scan ignores it and fails while any marker remains.
* **An automated permission check refuses to merge a PR without a human saying so.** Merging needs an explicit decision by a person.
* **Never tag `detector-freeze` by hand**: run the pre-flight. The held-out set can be run once.
